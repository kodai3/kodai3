大きなアイデアが来た。1 エージェントセッションには大きすぎ、霧に包まれている。ここから **行き先** までの道はまだ見えない。Wayfinding は、行き先へ突撃することではなく、その道を見つけること。このスキルは道をリポジトリの issue tracker 上の **共有地図** として引き、**decision ticket**（解決が判断である質問であり、実行するビルドのスライスではない）を 1 枚ずつ進め、ルートがはっきりするまで続ける。

行き先は作業ごとに違う。名付けることが地図作りの最初の行為で、すべての ticket の形を決める。手渡しして反復する spec かもしれないし、計画を始める前にロックする判断かもしれないし、データ構造の移行のようにその場で行う変更かもしれない。地図はドメイン非依存。エンジニアリングでも、コース内容でも、この形に合うものなら何でもよい。

## 計画し、やらない

Wayfinder の既定は **計画**。各 ticket は判断を解決し、道がはっきりし、誰かがやる前に決めることが残っていないとき地図は終わる。作業をやってしまいたくなる衝動は、たいてい地図の縁に着いた合図であり、手渡しの時である。作業は **Notes** でこの既定を上書きし、実行を地図の中へ持ち込める。それがなければ、成果物ではなく判断を出す。

## 名前で指す

地図も ticket も issue なので **名前** がある。タイトルである。人が読むもの（語り、地図の Decisions-so-far）では、その名前で指す。裸の id、番号、slug では指さない。`#42, #43, #44` の壁は読めない。名前は一目で読める。id と URL は消えない。名前がそのリンクを包む。それらは名前の *中* に乗り、名前の代わりには立たない。

## 地図

地図はこのリポジトリの issue tracker 上の 1 issue で、ラベルは `wayfinder:map`。正本の成果物。ticket は地図の子 issue。

地図は **索引** であり、倉庫ではない。決まった判断を列挙し、詳細を持つ ticket を指す。判断はちょうど 1 箇所、その ticket に住む。地図は言い直さない。要旨を書いてリンクする。

**地図、子 ticket、blocking、frontier のクエリが物理的にどこに住むかは tracker 固有。** issue tracker は渡されているはず。なければ `/setup-matt-pocock-skills` を案内する。このリポジトリでの表現は、tracker ドキュメントの "Wayfinding operations" を見る。tracker がなければ、ローカル Markdown tracker を既定にする。

### 地図の本文

低解像度の地図全体。セッションごとに 1 回読む。開いている ticket は **列挙しない**。開いている子 issue であり、クエリで見つける。

```markdown
## Destination

<この地図の終わりが何か。この作業が道を探している spec、判断、変更。1〜2 行。ticket を選ぶ前に、毎セッションがこれに向き直る。>

## Notes

<ドメイン。毎セッションが相談すべきスキル。この作業でずっと使う好み>

## Decisions so far

<!-- 索引: 閉じた ticket ごとに 1 行。関連性を判断できる分量。詳細はリンク先の ticket へズーム -->

- [<閉じた ticket のタイトル>](link): <答えの 1 行要旨>

## Not yet specified

<!-- 「Fog of war」: まだ ticket にできない、スコープ内の霧。frontier が進むと卒業する -->

## Out of scope

<!-- 「Out of scope」: 行き先の向こうと決めた作業。閉じ、卒業しない -->
```

### Ticket

各 ticket は地図の **子 issue**。tracker の issue id がアイデンティティ。本文は質問。1 セッション 100K トークンに収まる大きさ:

```markdown
## Question

<この ticket が解決する判断または調査>
```

各 ticket は `wayfinder:` ラベルを 1 つ持つ。`research`、`prototype`、`grilling`、`task`（[Ticket Types](#ticket-types)）。

セッションは作業の **前に**、地図を運転している開発者へ assign して ticket を **claim** する。並行セッションがそれを飛ばせるように。その assignee が claim そのもの。開いていて未 assign の ticket は未 claim。

Blocking は tracker の **native** な依存関係を使う。tracker 自身の UI で frontier が *視覚的に* 描かれることが本質で、人は地図を開かずに取れるものを見る。native blocking がない tracker だけ、本文の慣例に落とす。ticket は、それを block する ticket がすべて閉じたとき **unblocked**。**frontier** は、開いていて、unblocked で、未 claim の子。既知の縁。

答えは本文の一部ではない。解決時に記録する（[地図を進める](#地図を進める)）。解決中に作った asset は issue からリンクし、貼り付けない。

## Ticket Types

すべての ticket は **HITL**（human in the loop。自分が話す人間と一緒に進める）か **AFK**（エージェント単独）か。HITL の ticket は、そのライブのやり取りを通してだけ解決する。エージェントが人間側の答えを代行しない（自分の質問に自分で答える grilling は、これを破っている）。

- **Research**（AFK）: ドキュメント、第三者 API、ナレッジベースなどのローカル資源を読み、判断が待つ事実を出す。Skill tool で `research` を呼ぶサブエージェントが解決する。今の作業ディレクトリの外の知識が必要なときに使う。
- **Prototype**（HITL）: 安く粗い具体物（アウトライン、粗い案、stub、UI / ロジックのコード）を作って議論の解像度を上げる。Skill tool で `prototype` を呼ぶ。プロトタイプを asset としてリンクする。「どう見えるべきか」「どう振る舞うべきか」が鍵のときに使う。
- **Grilling**（HITL）: 会話。既定。Skill tool を必ず 2 回呼ぶ。対象は `grilling` と `domain-modeling`。
- **Task**（HITL または AFK）: *判断* の前に必要な手作業。決めることも、プロトタイプも、調査もないが、それが終わるまで議論が止まる。API を評価するためにサービスへ登録する、アクセスを用意する、形を見るためにデータを移す。決定ではなく *やる* 唯一の型で、行き先を届けるためではなく、判断のロックを外すために席を得る。できるところはエージェントが単独で進める（AFK）。そうでなければ人に正確なチェックリストを渡す（HITL）。作業が終わったら解決。答えは、何をしたかと、後続 ticket が依存する事実（認証情報の場所、新しい URL、行数）を記録する。

## Fog of war

地図は *意図的に* 不完全。まだ見えないものを描かない。生きている ticket の向こうに **fog of war** がある。来ることが分かっているが、まだ開いている質問にぶら下がっているのでピン留めできない判断と調査の、薄い眺め。ticket を解くとその先の霧が晴れ、いま指定できるものが新しい ticket へ卒業する。行き先までの道がはっきりし、ticket が残らなくなるまで 1 枚ずつ。

地図の **Not yet specified** が、その薄い眺めを書く場所。疑っている質問、後で戻る領域。行き先 *へ向かう* 未発見の frontier。ここにあるものはすべてスコープ内で、ticket にするほど鋭くないだけ。眺めが許す粗さまたは細かさで書く。協力者が、作業の向かう先を読む道標にもなる。

**霧か ticket か。** 試すのは、*いま答えられるか* ではなく、質問をいま正確に述べられるか。

- **ticket にする**: 質問がすでに鋭い。block されていてまだ動けなくても。
- **Not yet specified にする**: その鋭さでまだ言えない。霧を ticket サイズに事前分割しない。ticket より粗い。frontier が届いたとき、1 つの塊が複数 ticket になることも、ゼロになることもある。

**Not yet specified** から除くもの: すでに決まったこと（Decisions so far）、すでに生きている ticket、対象外（次の節）。

## Out of scope

霧は行き先 *へ向かって* だけ集まる。行き先がスコープを固定するので、その向こうの作業は **out of scope**。霧ではなく、**Not yet specified** にも入らない。地図の **Out of scope** 節に置く。*この* 作業から意識して外した作業。鋭さではなくスコープがここに置く。

対象外の作業は卒業しない（frontier は行き先で止まる）。戻るのは行き先を描き直したときだけで、再開ではなく新しい作業として。

対象外と決めるのは、ルート上の一歩ではなく、スコープ行為。すでに存在する ticket が行き先の向こうだと分かったら（地図作りの誤スコープ、または解決が露わにした）、**閉じる**（閉じた ticket は frontier から明確に外れる）。**Out of scope** に 1 行残す。要旨と、なぜ対象外か。閉じた ticket へリンクする。**Decisions so far** には入れない。そこは実際に歩いたルートを記録する。スコープ境界はその一歩ではない。

## 起動

2 モード。どちらでも **1 セッションで解く ticket は 1 枚まで**。research ticket は例外。

### 地図を描く

ユーザーが粗いアイデアで起動する。

1. **行き先に名前を付ける。** Skill tool を 2 回呼ぶ。対象は `grilling` と `domain-modeling`。この地図が道を探しているもの（spec、判断、変更）を固定する。行き先がスコープを決めるので、先に固める。
2. **frontier を地図にする。** もう一度 grill する。今度は **breadth-first**。1 本を深くせず空間全体へ広げ、開いている判断と、いま取れる最初の一歩を出す。**霧が出なければ**（行き先までの道がすでに見え、旅全体が 1 セッションに収まる）地図は要らない。止めて、どう進めるかユーザーに聞く。
3. **地図を作る**（ラベル `wayfinder:map`）。Destination と Notes を埋め、Decisions-so-far は空、霧は **Not yet specified** にスケッチする。
4. **いま指定できる ticket を** 地図の子 issue として作り、**2 パス目** で blocking の辺を張る（issue は id がないと互いに参照できない）。配線が frontier と blocked に分ける。まだ指定できないものは霧に残す。**Not yet specified**。
5. **research サブエージェントを出す。** いま作った各 `research` ticket について、Skill tool で `research` を呼ぶサブエージェントを並列で走らせ、調査結果を捨てブランチ `research/` に残し、ticket から context pointer を付ける。
6. 止まる。地図作りは 1 セッションの仕事。手で解くことはしない。

### 地図を進める

ユーザーが地図（URL または番号）で起動する。ticket は **任意**。なければユーザーではなく、次の判断を選ぶ。

1. **地図** を読む。低解像度の眺め。すべての ticket 本文ではない。
2. ticket を選ぶ。ユーザーが指名したらそれを使う。でなければ順序どおり最初の frontier ticket。 **Claim する**: 作業の前に自分へ assign する。
3. 解く。**必要ならズーム**: 関連する、または閉じた ticket の本文をオンデマンドで取る。`## Notes` が名指しするスキルは Skill tool で呼ぶ。迷ったら Skill tool を 2 回。対象は `grilling` と `domain-modeling`。
4. 解決を記録する。答えを **resolution comment** として投稿し、issue を **閉じ**、地図の Decisions-so-far に **context pointer** を追記する。
5. 新たに見えた ticket を足す（作ってから張る）。答えが指定可能にした霧を卒業させ、卒業した塊を **Not yet specified** から消し、新しい ticket にだけ住ませる。答えが、この ticket または別の ticket が行き先の向こうだと示したなら、ルート上で解くのではなく **対象外にする**。判断が地図の他部分を無効にしたら、それらの ticket を更新または削除する。

ユーザーは unblocked な ticket を並行で走らせることがある。他セッションが tracker を同時に編集している前提で動く。
