# Prototype

プロトタイプは **問いに答える捨てコード**。質問が形を決める。

## 枝を選ぶ

どの問いに答えているかを特定する。ユーザーのプロンプト、周囲のコード、ユーザーがいれば聞く:

- **「このロジック / 状態モデルはしっくり来るか？」** → [LOGIC.md](LOGIC.md)。1 つの共有可能な HTML ファイル（自由に押せるボタン + タブ付きガイド付きウォークスルー）。紙の上では考えにくいケースへ状態機械を押し、開発者でなくても運転できる。
- **「どう見えるべきか？」** → [UI.md](UI.md)。1 つのルート上に、構造的に大きく違う UI 案を複数作り、URL の search param と画面下のフローティングバーで切り替える。

2 つの枝は成果物が全く違う。間違えるとプロトタイプ全体が無駄になる。質問が本当に曖昧でユーザーに届かないなら、周囲のコードに合う枝を既定にする（バックエンドモジュール → ロジック、ページやコンポーネント → UI）。仮定はプロトタイプの先頭に書く。

## 両方に効く規則

1. **初日からの捨てコードであり、そう明示する。** プロトタイプのコードは、実際に使われる場所の近く（対象モジュールやページの隣）に置き、文脈が分かるようにする。ただし名前で、プロダクションではなくプロトタイプだとカジュアルな読者に分かるようにする。捨てる UI ルートは、プロジェクトがすでに使うルーティング慣例に従う。新しいトップレベル構造を発明しない。
2. **起動は自明。** UI プロトタイプはプロジェクトのタスクランナーの 1 コマンドから始まる: `pnpm <script>`、`python <module>`、`bun <script>` など。ロジックデモはユーザーがダブルクリックする 1 HTML。どちらも、始めるために考える必要がない。
3. **既定で永続化しない。** 状態はメモリに住む。永続化はプロトタイプが *確かめている* ものであり、依存すべきものではない。質問が明示的に DB を含むなら、スクラッチ DB、または "PROTOTYPE, wipe me" と分かるローカルファイルを叩く。
4. **磨きは省略。** テストなし。プロトタイプを *走らせる* 以上のエラー処理なし。抽象なし。速く学ぶことが目的。
5. **状態を出す。** すべての操作の後（ロジック）、またはすべてのバリアント切り替え（UI）で、関係する状態を全部印刷または描画し、何が変わったか見えるようにする。
6. **終わったら残す。** 検証した判断は本番コードへ折り込み、プロトタイプ自体は **一次情報** として残す。main の外の捨てブランチへ commit し、実装 issue にそのブランチへの context pointer を残す。答え（評決と、それが閉じた質問）も issue または commit に残す。main が持つのは検証した判断だけ。
